# Contributing to ASP

ASP is a **proposal**, not an adopted standard. The most valuable contributions at this stage are critical ones: tell us where the proposal is wrong, unclear, incomplete or unnecessary.

## Ways to contribute

- **Comment on the proposal.** Open an issue for a question, an objection or an alternative design. Please say which part you are commenting on: state vocabulary, events, liveness, governance, transport binding, mappings or security.
- **Take up an open issue.** The draft lists open questions for version 0.2, for example a standard credential profile, bindings for topologies without a dedicated status server, and a registry of governance reason codes. Arguments and prototypes on any of them are welcome.
- **Report implementation experience.** If you try ASP with a real framework, protocol or deployment, an issue describing what mapped cleanly and what did not is extremely useful.
- **Improve the examples.** Pull requests that fix, simplify or extend the examples, the draft schema or the illustrative implementations are welcome.

## Pull requests

- Keep each pull request focused on one change.
- For changes to the proposal itself, open an issue first so the change can be discussed.
- Sign off your commits (`git commit -s`) to certify the [Developer Certificate of Origin](https://developercertificate.org/).

## Conduct

Be respectful and assume good faith. Disagreement about the design is expected and welcome; personal attacks are not.
